# 归因逻辑规则文档

> ⚠️ **修改联动**：本文件与 `attribute.py`（同目录）强绑定。
> - 改规则 → 先更新本文件，再同步修改 `attribute.py`
> - 改代码 → 先确认本文件规则，修改后同步更新本文件
> 两者不同步 = 归因结果不可信
>
> **关联文件**：
> - V1/V2 校验规则 → `../promo/promo_logic.md`
> - V3 校验 + 人工校验触发规则 → `validation_logic.md`（同目录）

## 一、共用归因说明

### 1.1 前置技术说明

#### 促销名称标准化规则

匹配前对促销名称做标准化处理：去除所有空格和噪音符号（`_`、`。`、`，`、`、`、`；`、`：`、`.`），去除首尾空白，**保留 `-`**（结构性分隔符）。标准化后做精确匹配。

#### 多值输出分隔符

二级_AI、三级_AI、四级_AI 多值统一使用中文逗号 `，` 分隔。读取历史结果时需兼容中文逗号、英文逗号和斜杠。

#### 一级冲突人工校验

一级由 `客服判断场景` 判断。若 `im-归因结果-AI` 推导出的一级与客服判断一级不一致，只写入「是否需要人工校验=是」和对应「人工校验内容」，不阻塞归因流程。

### 1.2 字段依赖清单

> AI 归因**只读本节列出的字段**，不读取其他字段。
> 字段缺失时，只有当该行归因路径实际用到该字段，才触发报错；未用到的字段缺失不报错。

| 到手价（竞品）| V3校验 + 价格类前置 | ✅ |
| Q划线价——同质化房型 | 同质化判断 | ✅ |
| 划线价（竞品）| 同质化判断 | ✅ |

#### 过程变量说明

归因脚本在计算过程中产生的中间变量，均由上述输入字段派生。

**同质化判断变量（携程专用）**：

| 变量名 | 计算方式 | 含义 |
|--------|---------|------|
| `roomid_match` | `Q RoomID == 竞品 RoomID`（字符串精确匹配）| RoomID 一致标志 |
| `lineprice_match` | `\|Q划线价 - 竞品划线价\| ≤ 0.1` | 划线价一致标志 |
| `is_homo` | `roomid_match AND lineprice_match` | 同质化标志：True→Category 1；False→Category 2 |

### 1.3 归因结果树（合法枚举）

归因逻辑的输出值不能超出此范围。

```
一级：异常
├── 二级：信息缺失 → 三级：客服分析结果未填写
└── 二级：未知原因

一级：无法归因
├── 二级：不可对比
│   ├── 三级：非C平台 / 民宿房 / 团购房 / 预售 / 已下单
├── 二级：无法查询到Croomid
├── 二级：同CroomidQ未露出，且归因时入住日期，SPA无法查询（携程前置触发）
└── 二级：QCroomid相同，划线价不同（携程前置触发）

一级：库存lose
├── 二级：物理房型缺失 → 三级：物理房型真实缺失 / 物理房型已售罄
├── 二级：酒店缺失
└── 二级：同质化房型缺失（同程）

一级：用户误解
├── 二级：对比酒店不一致 → 三级：对比酒店不一致
├── 二级：对比日期/房型/权益等不同 → 三级：对比日期不同 / 对比房型不同 / 对比权益不同
├── 二级：免费类权益lose
├── 二级：用户不认可积分优惠
├── 二级：用户没看到返现优惠
├── 二级：用户不认可券包优惠
└── 二级：错选乱选&未知原因 → 三级：错选乱选 / 未知原因

一级：价格lose（携程）
├── 二级：积分补贴lose → 三级：积分类lose
├── 二级：支付补贴lose → 三级：拿去花/信用购付款
├── 二级：产品报价缺失 → 三级：报价未接入 / 报价未露出
└── 二级：促销lose
    ├── 三级：商促+平促混合包装lose
    ├── 三级：商促/券未接入
    ├── 三级：平台券lose → 四级：定价券lose / 无对标券 / 未领券 / 已领取不能使用 / 超过限制用券量 / 无法拆解
    ├── 三级：身份类促销lose → 四级：优享会 / 出行身份 / 门店新客 / 学生身份
    └── 三级：政府券lose

一级：价格lose（同程）
├── 二级：促销lose（|Q划线价 - E划线价| ≤ 0.1）
│   ├── 三级：商家补贴lose → 四级：[E侧商促促销名称]
│   ├── 三级：平台补贴lose → 四级：定价lose / 平券lose / 大额券lose / 黑鲸优惠lose
│   ├── 三级：积分lose → 四级：多倍积分酒店lose / 非多倍积分酒店lose
│   └── 三级：返现lose
└── 二级：底价（|Q划线价 - E划线价| > 0.1）
    ├── 三级：E划线价更低 → 四级：E含商促 / E不含商促
    └── 三级：Q货源划线价更低 → 四级：E含商促 / E不含商促

一级：校验失败
└── 二级：V3错误
```

### 1.4 一级路由

**输入字段**：`客服判断场景`

**优先级（高 → 低）**：异常 > 无法归因 > 库存lose > 用户误解 > 价格lose

| 优先级 | 匹配条件 | 输出一级 |
|--------|---------|---------|
| 1 | 客服判断场景为空 | 异常 |
| 2 | 含 `roomid` | 无法归因 |
| 3 | 含 `不可对比平台` 或 `非可对比平台` 或 `非可比价平台` | 无法归因 |
| 4 | 含 `民宿` | 无法归因 |
| 5 | 含 `团购` | 无法归因 |
| 6 | 含 `预售` | 无法归因 |
| 7 | 含 `已下单` | 无法归因 |
| 8 | 含 `更好更贵` 或 `更差更贵` | 库存lose |
| 9 | 含 `物理房型` | 库存lose |
| 10 | 含 `酒店缺失` 或 `无该酒店` 或 `没有该酒店` | 库存lose |
| 11 | 含 `酒店不一致` 或 `入离` 或 `入住日期` 或 `入住时间` 或 `房型不一致` | 用户误解 |
| 12 | 含 `价格不lose` 或 `不lose` 或 `价格不` | 用户误解 |
| 13 | 含 `同质化` | 价格lose |
| 14 | 含 `lose` | 价格lose |
| 15 | 以上均不满足 | 异常 |

### 1.5 各分类归因逻辑（异常 / 无法归因 / 库存lose / 用户误解）

#### 异常类

| 二级 | 触发条件 | 三级 |
|------|---------|------|
| 信息缺失 | 客服判断场景为空 | 客服分析结果未填写 |
| 未知原因 | 以上均不满足（兜底）| 空 |

#### 无法归因类

| 二级 | 触发条件 | 三级 |
|------|---------|------|
| 不可对比 | 含`不可对比平台`/`非可对比平台`/`民宿`/`团购`/`预售`/`已下单` | 非C平台 / 民宿房 / 团购房 / 预售 / 已下单 |
| 无法查询到Croomid | 含 `roomid` | 空 |

> `同CroomidQ未露出，且归因时入住日期，SPA无法查询` 和 `QCroomid相同，划线价不同` 两个二级由携程价格类前置检查触发（见第二节）。

#### 库存lose类

| 二级 | 触发条件 | 三级 |
|------|---------|------|
| 物理房型缺失 | 含 `物理房型` | 含「已订完/售罄/满房/无房」→物理房型已售罄；含「缺失/暂无/无该房型」→物理房型真实缺失 |
| 酒店缺失 | 含 `酒店缺失` 或 `无该酒店` 或 `没有该酒店` | 空 |

#### 用户误解类

> 用户误解类二级、三级只依赖 `im-归因结果-AI`。

| 二级 | 触发条件 | 三级 |
|------|---------|------|
| 对比酒店不一致 | im 含 `酒店不一致` | 对比酒店不一致 |
| 对比日期/房型/权益等不同 | im 含 `入离不一致`/`房型不一致`/`同质化权益` | 对比日期不同/对比房型不同/对比权益不同（可多个）|
| 免费类权益lose | im 含 `免费权益` | 空 |
| 用户不认可积分优惠 | im 含 `积分` | 空 |
| 用户没看到返现优惠 | im 含 `返现` | 空 |
| 用户不认可券包优惠 | im 含 `券包` | 空 |
| 错选乱选&未知原因 | im 含 `错选乱选`/`未知原因`；或用户误解一级命中但 IM 无可用细分 | 错选乱选 / 未知原因 |

## 二、携程价格归因规则

> **适用条件**：`price_rule_set == "xiecheng"`

### 2.1 价格类前置检查（无法归因场景）

在二级归因前，先检查以下两个特殊场景，命中则直接输出无法归因。**优先级：过入住日期检查 > 划线价不同检查。**

| 场景 | 触发条件 | 一级_AI | 二级_AI |
|------|---------|---------|---------|
| 过入住日期无法查询分销状态 | 【是否分销】= 过入住日期无法查询 | 无法归因 | 同CroomidQ未露出，且归因时入住日期，SPA无法查询 |
| 划线价不同（非产品报价缺失场景）| \|Q划线价-竞品划线价\| > 0.1 **AND** 【是否分销】≠ 未分销 **AND** 【是否露出】不含"未露出" | 无法归因 | QCroomid相同，划线价不同 |

> **例外**：当【是否分销】= 未分销 或【是否露出】含"未露出"时，即便划线价不同也不触发此前置检查——这类场景属于产品报价缺失，由二级判断处理。

### 2.3 二级判断（Category 1 / Category 2 双路径）

**Category 1（is_homo = True）**：Q RoomID == 竞品 RoomID 且 |Q划线价 - 竞品划线价| ≤ 0.1，只判以下三项：

| 二级 | 触发条件 |
|------|---------|
| 积分补贴lose | 竞品积分类金额 > Q积分金额 |
| 支付补贴lose | 竞品第三方补贴金额 > 0 |
| 促销lose | 有任一促销lose三级命中（子级驱动）|

**Category 2（is_homo = False）**：优先判产品报价缺失，不满足再判促销/积分/第三方：

| 判断顺序 | 二级 | 触发条件 |
|---------|------|---------|
| 1（优先，命中即停止）| 产品报价缺失 | 【是否分销】= 未分销 → 三级：报价未接入，停止 |
| | 产品报价缺失 | 【是否分销】含"分销" AND【是否露出】含"未露出" → 三级：报价未露出，停止 |
| 2（产品报价缺失不命中时）| 积分补贴lose | 竞品积分类金额 > Q积分金额 |
| | 支付补贴lose | 竞品第三方补贴金额 > 0 |
| | 促销lose | 有任一促销lose三级命中（子级驱动）|

### 3.2 判断优先级与执行顺序

```
Step 1: 划线价一致性判断
  若 |Q划线价——同质化房型 - 划线价（竞品）| > 0.1
  → 二级_AI=底价，进入 Step 1b，停止

  Step 1b: 底价三级/四级
    三级：划线价（竞品）< Q划线价 → E划线价更低
          划线价（竞品）> Q划线价 → Q货源划线价更低
    四级：e_shangcu_total > 0 → E含商促；否则 → E不含商促

Step 2: 促销三级归因（可多选）
  2a. e_shangcu_total > q_shangcu_total → 商家补贴lose
  2b. e_pingtai_total > q_pingtai_total → 平台补贴lose
  2c. e_jiefen > q_jiefen              → 积分lose
  2d. e_fanxian > 0                    → 返现lose

Step 3: 四级归因
  [商家补贴lose] → E侧商促促销名称（多个逗号分隔）
  [平台补贴lose] → 定价lose / 平券lose / 大额券lose / 黑鲸优惠lose（可多个）
  [积分lose]     → 多倍积分酒店lose / 非多倍积分酒店lose（依赖"是否多倍积分酒店"字段）

Step 4: 兜底检查
  若三级全部未命中
  → 是否需要人工校验=是
    人工校验内容=价格类但无法确定lose原因（Q支付价=X，E支付价=Y）
```

### 3.3 平台补贴lose四级判断逻辑

## 六、归因结果统计说明

> 对应 `attribute.py` 中的 `_generate_attribution_summary()` 和 `_generate_attribution_logic()` 函数。
> 统计规则同时适用于携程和同程。

### 6.1 归因结果汇总 Sheet：V1-V4 四版本统计

「归因结果汇总」Sheet 纵向堆叠四张统计表，分组维度逐级加深：

| 版本 | 分组维度 | 说明 |
|------|---------|------|
| V1 | 一级_AI | 一级汇总，每个一级一行 |
| V2 | 一级_AI + 二级_AI | 二级细分，每个一级头部追加小计行 |
| V3 | 一级_AI + 二级_AI + 三级_AI | 三级细分 |
| V4 | 一级_AI + 二级_AI + 三级_AI + 四级_AI | 四级细分（见 6.2） |

每版本包含列：一级、二级、三级、四级（无则显示 `/`）、数量、占比。

### 6.2 V4 路径展开规则（_build_v4_paths_df）

V4 统计使用 `_l3_l4_paths` 字段而非直接分割 `三级_AI`/`四级_AI` 字符串，原因是三级和四级均可为多值（如"商家补贴lose，积分lose"），直接 split + 笛卡尔积会产生错误配对。

**展开规则**：

1. 若该行有 `_l3_l4_paths`（列表，元素为 `(三级item, 四级item)` 元组）：
   - 对每个 `(l3, l4)` 对各输出一行
   - 同时检查三级原始值中有无未被 `_l3_l4_paths` 覆盖的三级项（如"返现lose"无四级）→ 这些三级项以 `(l3, '')` 形式输出一行
2. 若该行没有 `_l3_l4_paths`（如早期数据）：
   - 有四级值时，四级逐项与第一个三级项配对输出；剩余三级项各输出一行（四级为空）
   - 无四级值时，三级逐项各输出一行（四级为空）

**无四级的路径必须出现在 V4 统计中**：用户误解、库存lose、无法归因、异常等一级的路径通常止于三级甚至二级，四级列以空串补位，正常参与分组计数，不得丢弃。

### 6.3 小计行位置规则

V2/V3/V4 中，每个一级分组的**小计行在该分组第一行**（而非末尾）。

```
价格lose    【小计】    /    /    N    xx%    ← 先写小计
价格lose    促销lose    平台补贴lose    定价lose    n1    x1%
价格lose    促销lose    平台补贴lose    平券lose    n2    x2%
...
用户误解    【小计】    /    /    M    yy%    ← 下一个一级，先写小计
...
```

### 6.4 归因逻辑 Sheet 格式

「归因逻辑」Sheet 使用与 V4 相同的 `_build_v4_paths_df` 展开逻辑，去重后输出：

- **列**：归因1级、归因2级、归因3级、归因4级、归因规则（空白，供人工填写）
- **无数量列**：每条路径出现一次，不统计频次
- 路径按一至四级字典序排序
- 用于人工梳理和标注各场景的归因规则描述
