# V3 数据一致性校验规则

> ⚠️ **修改联动**：本文件与 `attribute.py`（同目录）强绑定。
> - 改 V3 规则 → 先更新本文件，再同步修改 `attribute.py`
> - 改代码 → 先确认本文件规则，修改后同步更新本文件
> 两者不同步 = 归因结果不可信
>
> **关联文件**：V1 金额校验 / V2 促销匹配校验规则见 `../promo/promo_logic.md`（由促销校验模块执行）。

---

## 一、校验体系概览

| 校验 | 执行模块 | 时机 |
|------|---------|------|
| V1 金额校验 | 促销校验模块（validate.py）| 归因前，与IM归因并行 |
| V2 促销匹配校验 | 促销校验模块（validate.py）| 归因前，与IM归因并行 |
| V3 数据一致性校验 | 归因模块（attribute.py）| 一级路由之后，二级归因之前 |

---

## 二、V3 数据一致性校验

**执行时机**：一级路由（基于客服判断场景）完成后，得到一级结果，再检查支付价是否与一级结论一致。

**失败处理**：V3 失败时，该行输出 `一级_AI=校验失败`，不继续归因。

### 校验规则

| 矛盾场景 | 校验条件 | 失败输出 |
|---------|---------|---------|
| 路由为用户误解但价格实际lose | 一级路由结果=用户误解 且 Q支付价 > 竞品支付价 | 一级_AI: 校验失败 / 二级_AI: V3错误 / 归因备注: "V3错误：用户误解类但Q支付价——同质化房型>到手价（竞品）" |
| 路由为价格lose但价格实际不lose | 一级路由结果=价格lose 且 Q支付价 ≤ 竞品支付价 | 一级_AI: 校验失败 / 二级_AI: V3错误 / 归因备注: "V3错误：价格类但Q支付价——同质化房型≤到手价（竞品）" |

> 异常 / 无法归因 / 库存lose 类暂无可用字段做一致性校验，不覆盖。
>
> 支付价为空时跳过 V3 校验。

## 三、人工校验触发规则

以下情况触发 `是否需要人工校验=是`，原因写入分类列结构（替代原 `人工校验内容` 单列）：

| 人工校验分类 | 输出列 | 触发场景 | 写入内容格式 |
|------------|-------|---------|------------|
| 金额校验 | `金额校验_详情` | V1 校验失败（促销模块传递） | `真实错误:V1错误：...` |
| 促销匹配 | `促销匹配_详情` | V2 校验失败（促销模块传递） | `真实错误:V2错误：...` |
| 字段缺失 | `字段缺失_详情` | 同程积分lose但多倍积分酒店字段为空 | `价格类字段缺失:是否多倍积分酒店为空，积分lose四级待确认` |
| 字段缺失 | `字段缺失_详情` | 同程/携程价格类底价字段缺失 | `价格类字段缺失:...` |
| 归因不完整 | `归因不完整_详情` | 同程价格类但无法确定lose原因 | `价格类但无法确定lose原因（Q支付价=X，E支付价=Y）` |
| 归因不完整 | `归因不完整_详情` | 兜底验证：im=未知原因+cs不lose+Q含积分 | `兜底验证:im=未知原因+cs不lose+Q含积分` |
| 归因不完整 | `归因不完整_详情` | 模糊场景：无相同浏览记录 | `模糊场景:无相同浏览记录` |
| 归因不完整 | `归因不完整_详情` | IM归因说明含"新发现场景" | `新场景:[im-归因结果-AI内容]` |
| 归因多重校验 | `归因多重校验_详情` | 路由冲突（kf一级 ≠ im一级） | `路由冲突:kf=X/im=Y` |
| 归因多重校验 | `归因多重校验_详情` | 兜底验证：库存lose | `兜底验证:库存lose-[二级]` |
| 归因多重校验 | `归因多重校验_详情` | 兜底验证：价格不lose + 错选乱选/未知原因/积分 | `兜底验证:价格不lose+错选乱选` 等 |

**促销校验原因过滤规则**：
- V1/V2 促销校验原因来自促销模块 `case_audit`，只在最终 `一级_AI=价格lose` 时写入人工校验。
- 若最终 `一级_AI` 不是 `价格lose`，则不再写入促销校验原因（`真实错误:V1...` / `真实错误:V2...`），因为这些场景无需再人工复核促销。
- 其他人工原因（字段缺失、路由冲突、归因不完整、兜底验证等）不受此过滤影响。

**输出列说明**：
- `是否需要人工校验`：存在任意触发项时写 `是`
- `人工校验分类`：活跃分类名（顿号分隔），如 `字段缺失、归因不完整`
- `{分类}_详情`：该分类下所有原因（分号分隔），共 5 列

## 四、im一级推导列

`im一级推导` 列由 `_route_by_im()` 计算，每行均输出（`attribute_row()` 正常完成时）。  
V3 校验失败的早返回行此列为空。

**推导规则**（同路由冲突检测使用相同函数）：

| im-归因结果-AI 含关键词 | 推导一级 |
|-----------------------|---------|
| 非C平台 / 已下单 / 民宿 / 团购 | 无法归因 |
| 酒店不一致 / 房型不一致 / 入离不一致 / 同质化权益 / 无相同浏览记录 / 免费权益 / 积分 / 错选乱选 / 未知原因 / 未领券 | 用户误解 |
| 酒店缺失 / 去哪儿房型缺失 / 物理房型缺失 / 房型缺失 / 同质化房型缺失 | 库存lose |
| 同质化lose / 价格高 / 去哪儿价格高 | 价格lose |
| 空或无法识别 | 不参与对比 |

---

## 五、路由冲突检测逻辑

**逻辑**：将 `im-归因结果-AI` 解析为一级（同 `im一级推导` 规则），与 `客服判断场景` 路由的一级对比。冲突时写入 `归因多重校验_详情`。
