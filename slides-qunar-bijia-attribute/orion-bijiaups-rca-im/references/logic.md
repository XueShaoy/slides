# IM客服交互归因分类规则

> ⚠️ **修改联动**：本文件是 IM 归因的唯一规则来源，与 `orion-bijiaups-rca-im.md`（上级目录）绑定。
> - 改分类规则 → 先更新本文件，再告知下次执行IM归因时已更新规则
> - 本文件不直接绑定 Python 脚本（IM归因由 LLM 执行，不是 Python 脚本）
> - 但规则变更需同步更新 `attribution/standard_cases/` 中涉及用户误解类的 case

---

## 背景说明

去哪儿比价调研场景：用户填写问卷认为去哪儿价格贵后，被邀请上传竞品截图，客服介入核实。
本规则用于从客服与用户的IM对话中，识别用户认为去哪儿价格贵的真实原因。

支持比价的竞品平台：携程、美团、飞猪、同程（以下简称"四平台"）

---

## 输入格式

IM记录格式：`发送者: 内容 → 发送者: 内容 → ...`
发送者角色：`客服`（含"小驼"等昵称）/ `用户`
`[图片]` 标记表示发送了图片，无文字内容可分析。

---

## 分类体系

```
截图合规类           非C平台 / 已下单 / 民宿房 / 团购房
条件不一致类         酒店不一致 / 房型不一致 / 入离不一致 / 同质化权益 / 无相同浏览记录
用户感知类           免费权益 / 积分
错选乱选
未知原因
去哪同质化房型及价格贵类   酒店缺失 / 去哪儿房型缺失 / 房型一致去哪儿权益缺失 / 去哪儿价格高
新场景               未领券
```

## 叶节点枚举与判断规则

### 一、截图合规类

> 此类节点描述截图不符合比价要求，导致对比无法进行或需重新提交。

#### 1. 非C平台
**定义**：用户提供的竞品截图来自四平台以外的平台（如艺龙、booking、华住等）
**核心信号**：
- 客服说"只面向携程/美团/飞猪/同程"
- 客服说"这次调研不包含XX平台"

#### 2. 已下单
**定义**：用户提供了已下单/已支付状态的截图，不符合比价要求
**核心信号**：
- 客服说"已下单不对比"
- 客服说"需要未下单的截图"

#### 3. 民宿房
**定义**：用户提供的是民宿/青旅/共享住宿截图，非标准酒店
**核心信号**：
- 对话中明确提及民宿/青旅/共享房源
- 客服提示"仅支持标准酒店对比"

#### 4. 团购房
**定义**：用户比较的是团购价/活动特惠包
**核心信号**：
- 对话中提及团购/活动包价格
- 客服说该价格不在比价范围内

---

### 二、条件不一致类

> 此类节点描述用户在去哪儿和竞品之间对比的条件不相同，是用户认为贵的根因。

#### 5. 酒店不一致
**定义**：用户在去哪儿和竞品选择了不同的酒店
**核心信号**：
- 客服说"系统未查到相同酒店的浏览记录"／"酒店不一致"
- 客服提供酒店名称引导用户重新搜索
- 用户在A酒店填问卷却发了B酒店截图（比错了对象）

#### 6. 房型不一致
**定义**：用户在去哪儿和竞品选择了不同的房型
**核心信号**：
- 客服核实后指出去哪儿截图与携程截图房型名称不一致
- 客服询问"是否比对错房型"
- 需从客服核实话术中提取房型名称，与竞品截图房型对比

#### 7. 入离不一致
**定义**：用户在去哪儿和竞品选择了不同的入离店日期
**核心信号**：
- 客服说"系统未查到相同日期的浏览记录"
- 客服说"辛苦在我司浏览相同日期的价格"
- 客服指出具体日期要求重新浏览
- 用户自己说"日期看错了"/"浏览日期错了"（有具体条件时优先标此节点，而非错选乱选）

#### 8. 同质化权益
**定义**：用户比较的两个房型名称相同或相似，但包含的具体权益（早餐档次/取消规则/服务内容等）存在实质差异，导致价格不可直接对比
**核心信号**：
- 客服说"需要核实跟携程一样的规则报价"后，价格明显低于用户看到的价格
- 客服指出两侧含早/取消政策/其他服务内容不一致
- 注意与**房型不一致**的区别：房型不一致是房型名称本身不同；同质化权益是名称相同但权益内容有差异

#### 9. 无相同浏览记录
**定义**：客服明确说明无相同浏览记录，但未指明是哪个具体条件（酒店/房型/日期）不一致
**优先级**：低于酒店不一致/房型不一致/入离不一致。若能明确具体哪个条件不一致，优先用对应标签
**核心信号**：
- 客服说"您的浏览记录无法找到"/"未查到相同浏览记录"，但未说明是哪个维度的差异

---

### 三、用户感知类

> 此类节点描述用户对价格/权益的主观认知差异。

#### 10. 免费权益
**定义**：用户认为竞品提供了去哪儿没有的免费权益（早餐/接机/停车/房型升级等）
**核心信号**：
- 用户说"XX是免费的"/"竞品有免费XX"
- 用户认为该权益价值应计入比价
- 客服确认是权益差异导致的价格感知差异
- 注意与**同质化权益**的区别：免费权益是竞品额外提供去哪无的项目；同质化权益是同一项目（如早餐）档次/内容有差异

#### 11. 积分
**定义**：用户认为积分因素导致价格差异（包括：不认可积分算作优惠，或竞品积分抵扣力度更大）
**⚠️ 使用前提**：仅当用户在对话中主动提及积分才适用。若积分差异需通过系统核实、对话中用户未主动提及，标为**未知原因**。
**核心信号**：
- 用户说"积分是自己的"/"不应该算积分"/"不算积分去哪更贵"
- 用户说"积分是预支的"/"提前扣的奖励"
- 对话中明确对比两平台积分抵扣金额，竞品积分抵扣更多

---

### 四、错选乱选

**定义**：用户在填写问卷或比价过程中自身存在选择/判断错误，实际上并不认为去哪儿价格贵
**⚠️ 关键判断标准**：必须是**用户自己**在对话中说出来。客服核实去哪不贵但用户未表态 → 标**未知原因**，不得推断为错选乱选
**核心信号**：
- 用户明确说"看错了"/"点错了"/"选错了"/"以为便宜/贵"
- 用户在对话中主动说去哪更便宜/更实惠，意识到自己比价有误
- 用户表现出随机作答，目的是领取消费金而非真正觉得贵
- 用户原以为剔除某因素（如积分）后去哪价格仍贵，但客服核实后去哪实际不贵（比价前提有误）
**注意**：若用户说"日期看错了"/"酒店选错了"等（有具体条件），优先归入对应的条件不一致节点，而非此处

---

### 五、未知原因

**定义**：客服核实后确认去哪儿**不贵**，但用户未说明自己认为贵的原因
**触发条件**（同时满足）：
- 客服审核后确认去哪儿价格并不高于竞品
- 用户未主动说明原因，也未说自己看错/选错
**⚠️ 重要**：
- 客服确认去哪儿**不贵**且用户无表态 → 未知原因
- 客服确认去哪儿**确实贵** → 去哪儿价格高（见第六大类）；此时不归入未知原因
- 对话中断、用户消失无法确认客服核实结果 → 未知原因

---

### 六、去哪同质化房型及价格贵类

> 此类节点描述客服核实后确认去哪儿确实存在供给或价格上的客观劣势，是用户认为贵的真实原因。
> 与**条件不一致类**的区别：条件不一致是用户比价条件有误（调整后去哪儿不贵）；此类是条件对齐后去哪儿确实更贵或缺失对应供给。

#### 12. 酒店缺失
**定义**：用户比价的目标酒店在去哪儿平台上无对应资源
**核心信号**：
- 客服说"该酒店在我司暂无资源"/"我司未上线该酒店"
- 客服无法在去哪儿查到用户截图中的酒店

#### 13. 去哪儿房型缺失
**定义**：酒店在去哪儿有，但用户比价的对应房型不存在
**核心信号**：
- 客服说"该房型我司暂无"/"我司无对应房型"
- 客服无法在去哪儿找到与竞品截图相同的房型

#### 14. 房型一致，去哪儿权益缺失
**定义**：两侧有同名或同类房型，但去哪儿版本缺少竞品提供的关键权益（如免费取消、早餐、接机等），导致去哪儿实质上提供了更差的选项
**核心信号**：
- 客服确认房型存在，但指出去哪儿该房型无免费取消/不含早餐等竞品有的权益
- 注意与**同质化权益**（条件不一致类）的区别：同质化权益是两侧权益内容存在差异导致不可直接对比，调整后去哪儿不贵；此节点是去哪儿确实缺失该权益，无等价选项

#### 15. 去哪儿价格高
**定义**：客服审核后确认去哪儿价格确实高于竞品。具体的价格 lose 原因（底价/促销/积分等）由后续三级归因确定，IM 归因只需识别"客服确认去哪儿贵"这一事实。
**⚠️ 条件说明**：IM 对话中通常看不到完整的比价条件（酒店/房型/日期是否一致），因此**不要求条件完全对齐**，只看客服的核实结论和行为。
**核心信号**（满足其中之一即可）：
- 客服发放补偿（消费金）并说明去哪儿价格确实更贵（最严谨的判断依据）
- 客服明确告知去哪儿价格更高，如"我们确实比较贵"/"去哪儿这边确实贵一些"/"经核实价格确实有差异"
**⚠️ 与三级归因的边界**：IM 归因只判断"客服是否确认去哪儿贵"，不判断贵的具体原因（底价/促销/积分等）——那是三级归因的任务。

---

### 七、新场景

> 在上述枚举之外发现的新场景，标注后持续积累。

#### 未领券
**定义**：用户反馈最初未领取优惠券，导致看到的价格偏高
**核心信号**：
- 用户或客服提及用户未领券/忘记领券
- 从IM对话中无法进一步判断其他原因

## 分类注意事项

### 多轮次处理
用户可能多次发图（被要求重新上传）。分类应基于**用户首次上传截图后客服第一次审核的结果**，不因后续补发而改变归因。
- 第一轮截图不规范（非C平台/已下单/民宿房等）→ 以截图合规问题归因，即使用户后续补发了规范截图也不改变
- 第一轮截图规范，对比完成 → 以该轮对比结果归因（根因来自用户的表态，不是客服核实结论）
- 第一轮截图规范，对比未完成（用户消失/对话中断）→ 归为未知原因
**AI归因说明格式要求**：存在多轮截图时，应分轮次写清楚：第一轮截图情况及客服判断、第二轮（若有）截图情况及客服判断，归因依据哪一轮说明。

### 多场景并列
一条对话可能同时触发多个分类，用英文逗号分隔，如：`入离不一致,积分`

### 根因优先原则
目标：找到"用户在填写问卷时为什么觉得去哪儿价格贵"。
- 有具体条件错误（酒店/房型/日期/权益）→ 用条件不一致节点
- 用户自述看错/选错但有具体条件 → 条件不一致节点（比错选乱选更精确）
- 用户自述看错/选错无具体条件，或表示不认为贵 → 错选乱选
- 客服确认去哪儿**确实贵** → 去哪儿价格高（不管用户是否表态）
- 客服确认去哪儿**不贵**，用户无表态 → 未知原因

### 新场景处理
若发现上述枚举之外的新场景：
- 短标签：简短中文描述
- 说明列：以"新发现场景："开头，详细描述场景和判断依据

### 关键话术速查

| 客服话术 | 对应分类 |
|---------|---------|
| "只面向携程/美团/飞猪/同程" | 非C平台 |
| "已下单不对比"/"未下单截图" | 已下单 |
| "未查到相同酒店的浏览记录"/"酒店不一致" | 酒店不一致 |
| "未查到相同日期的浏览记录"/"辛苦浏览相同日期" | 入离不一致 |
| "是否比对错房型" / 指出两侧房型名称不同 | 房型不一致 |
| "核实跟携程一样的规则报价" + 价格差距明显 | 同质化权益 |
| "无相同浏览记录"（未说明具体条件） | 无相同浏览记录 |
| "该酒店在我司暂无资源"/"我司未上线该酒店" | 酒店缺失 |
| "该房型我司暂无"/"我司无对应房型" | 去哪儿房型缺失 |
| 确认房型存在但指出去哪儿缺少免费取消/早餐等竞品权益 | 房型一致去哪儿权益缺失 |
| 客服发放消费金补偿并说明去哪儿价格更贵 | 去哪儿价格高（最严谨信号，条件不要求完全对齐） |
| 客服说"我们确实比较贵"/"去哪儿这边确实贵一些"/"经核实价格确实有差异" | 去哪儿价格高 |
| 追问"您当时觉得贵的原因是什么" | 看用户回答决定分类 |
| 客服核实后确认去哪儿不贵，用户无表态 | 未知原因 |
